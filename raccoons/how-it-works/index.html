Companion to Night Shift at the Pet Door

How the pet door camera works

Two cameras, one question asked about 900 times a day, and a $1,000 computer in the house that answers it. What runs where, how the AI decides, how I test it, and what it costs.

What it does

One question, all day

Two cameras watch the house. When something moves, the system records a short movie, asks a vision AI what's in it, and tells us: a phone alert with a picture, a spoken message on the Google Home speakers, and an event on a web page where we can search everything the cameras have seen. The AI runs on my own computer, so no footage goes to an AI company.

The question is always the same: is there a person, legs, a cat, a dog, a raccoon, or some other animal?

  1. WatchOne watcher per camera copies the camera's video into short pieces and checks a few small frames a second for motion.
  2. CutMotion opens an event; a few seconds of quiet closes it. The movie runs from just before the motion to just after.
  3. AskFour frames go to the vision model on ada as one picture, with the question. It answers in JSON.
  4. TellA phone alert, a spoken announcement, and an upload to the server and web app.
The cameras

A Pi at the flap, a store camera on the porch

The pet door camera is a Raspberry Pi 4 pointed at the flap. It's been some version of that since 2020. The porch camera is a store-bought network camera that gives out a standard video stream (RTSP).

Each watcher uses ffmpeg to copy the camera's own video into short pieces, which takes almost no CPU, even on a Pi. At the same time it decodes a few small frames a second and checks them for motion.

Asking the AI

Four frames, one picture, six answers

From each movie, the watcher picks the four frames with the most motion and lays them out in a 2x2 grid, as one picture. That picture and the question go to a vision language model, Qwen3-VL 8B, running in Ollama on ada's graphics card.

What the model sees: one image, four moments from the movie.

The model has to answer in JSON:

{"person": false, "legs": false, "cat": true, "dog": false, "raccoon": false, "animal": true}

Everything after that is plain code acting on those six true/false answers. A cat at the pet door means a spoken "There's a cat at the door." A raccoon means a phone alert. A person on the porch means a picture on everyone's phone. If the first answer says "animal", a second, animal-only question double-checks which one.

One call takes about a second and a half. For the pet door there's also an early check on a single frame while the cat is still sitting there, so the speakers can announce her before she gives up and wanders off.

Picking a model

By measuring, not by feel

The first AI experiments, in August 2025, used Qwen2.5-VL in a 3-billion-parameter size, then a 7-billion one. I also tried Gemma 3 1B and a couple of others that weren't useful, and Llama 3.2 Vision, which worked but was slow. Today it's Qwen3-VL 8B.

What made the choice possible was a test set: 139 clips that I labeled by hand (118 from the pet door, 21 from the porch), and a script that runs a model over all of them and scores it. The rule since then: no change to the model, the question, the number of frames or the image size goes in unless the score says it's better.

That rule exists because of Percy. Between May and July 2026 the old setup called my cats "raccoon" about ninety times, mostly Percy and his ringed tail. When I went through 117 clips by eye, the earlier model was wrong on 47 of them. With the test set and the scores, those mistakes stopped.

The porch problem

A cat is two tokens

The porch was worse, and the reason was size. In the grid each frame is 512 pixels wide, and a cat on the porch is about 25 by 45 pixels. The model cuts pictures into tokens of about 32 by 32 pixels, so the cat was one or two tokens. The model could tell there was an animal, but not which one.

The fix was to crop each frame to the area that moved before building the grid. On the pet door, where a cat fills the frame, cropping helped some clips and hurt others, so the pet door doesn't crop. Same idea, measured separately for each camera.

Test clips all rightNo cropCrop to motion
Porch (21 clips)1119

On the porch the crop fixed all seven misnamed cats and broke nothing. On the pet door it fixed 8 clips and broke 9.

The porch has one more quirk: the camera draws its own green box around anything that moves, right into the video, and for a while the AI read that box on the railing post as a person.

What it costs

$1,000 up front, then electricity

Most of the porch's calls are motion with nothing there (wind, light, the green box), so cutting those false alarms would cut a paid bill almost in proportion.

On price alone, ada wouldn't pay for itself against the cheapest paid models. That isn't why I bought it. On my own machine the footage of my house stays at home, I can run 2,500 test checks to compare two settings without thinking about a bill, and I can try any open model the day it comes out.

The rest of the system

Server, web app, speakers

  • Server: a Java Spring Boot server on a small cloud machine stores every event, movie and picture.
  • Web app: a Vue 3 web app to browse and search events by label, camera and date. Tapping an event's labels lets us correct the AI, and those corrections become new test clips.
  • Sign-in: Google sign-in, with each new person approved by me, and device keys for the cameras.
  • Alerts: Telegram messages with a picture and a link to the movie, each sent once.
  • Speakers: spoken announcements on the Google Home, with a short, cute sentence the AI writes about the cat in the picture.
  • Keeping it running: health alerts when a camera drops off, a daily report, and version numbers on every piece so I know what's running where.
How it got built

2020 by hand, 2026 with help

The first version, in 2020, was mine: the Pi camera code, a Java server and a Vue web page, written over a couple of months, with "working version!!!" in the commit log on March 12th. The AI part started in August 2025 as Bash scripts calling Ollama.

Since October 2026 I've built most of it with Claude Code as a pair programmer: the camera watcher that replaced the old capture code, the porch camera, the test scoring, the new web app, the announcements and the move to a new server. I decided what to build and checked the results, and it wrote much of the code, faster than I could have alone. I'm saying that plainly because it's true, and because it's part of what made this fun.
